# Cache Warmup on Startup

## Problem
When the Rails container restarts, Redis cache may be empty, causing:
- Spinners on free agents page that never resolve
- Slow initial page loads
- Background jobs need to repopulate cache (takes minutes)

## Solution
Automatically warm the cache on startup by loading stats from the `player_stats` database table (fast) instead of re-fetching from MLB API.

## Usage

### Manual Warmup
```bash
# Quick warmup - top 100 free agents (5-10 seconds)
docker exec players-web-qa rails cache:warmup_quick

# Full warmup - all players with stats (1-2 minutes)
docker exec players-web-qa rails cache:warmup
```

### Automatic Startup Warmup

**Option 1: Procfile (Recommended)**

Update `Procfile` to run warmup before starting server:

```ruby
web: bin/warmup-cache && bin/rails server -b 0.0.0.0
```

**Option 2: Docker Compose Command**

In `docker-compose.yml`, modify the web service command:

```yaml
services:
  players-web-qa:
    image: ghcr.io/jamiepinkham/players:jp-consolidated-fa-improvements
    command: sh -c "bin/warmup-cache && bin/rails server -b 0.0.0.0"
```

**Option 3: Manual After Restart**

After restarting the container, run:

```bash
docker exec players-web-qa bin/warmup-cache
```

## How It Works

1. **Quick Warmup** (`cache:warmup_quick`):
   - Loads top 100 free agents from database
   - Writes to Redis cache
   - Completes in 5-10 seconds
   - Runs in background, doesn't block startup

2. **Full Warmup** (`cache:warmup`):
   - Loads all players with stats from database
   - Prioritizes free agents
   - Completes in 1-2 minutes
   - Use for maintenance/after data imports

## Testing

Verify cache is populated:

```bash
docker exec players-web-qa rails runner '
cache_key = "player_stats:darnatr01:2025"
if Rails.cache.exist?(cache_key)
  puts "✓ Cache working"
else
  puts "✗ Cache empty"
end
'
```

## Notes

- Warmup uses **database records**, not MLB API (fast & reliable)
- Cache expires after 24 hours (regenerated by background jobs)
- Stats must already exist in `player_stats` table (run `rails stats:populate` first)
- Quick warmup is sufficient for normal operation
- Full warmup useful after running `players:remove_ineligible` cleanup
